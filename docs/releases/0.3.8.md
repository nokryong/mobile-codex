# 0.3.8

Android `versionCode 73`, ARM64, Android 10+.

- Error reports now identify the operation that failed and use fixed categories for timeouts, I/O, storage, permissions, RPC failures and supported Codex error types such as usage/context limits and upstream connection/authentication failures. Unknown failures remain explicitly unclassified. Raw error messages, stack traces, account details, conversation content, paths and tokens are never included.
- Startup measurements belong to the failed launch and action. Later login/chat errors, rollback attempts and replacement processes cannot reuse an earlier launch's counters. Later disconnects record current process state.
- Missing counters, elapsed time and process state are `null`, rather than misleading measured zeros or `false`. Preview and explicit consent still freeze the exact 27-field payload; retries keep the same receipt.
- Reports retain the actual app version. Earlier builds could label 0.3.7 as 0.3.6 because of a stale allow-list. The relay accepts bounded numeric release versions for schema 2 while preserving schema 1 validation and grouping for existing installations.

The relay must be upgraded before releasing this APK. The rollout verifies a schema-2 report with null measurements, its idempotent retry, exact public GitHub payloads and a legacy schema-1 report. Existing Redis receipts and reports are retained; no credentials or abuse limits change.

This release improves diagnostic evidence. It does not establish or fix the unknown underlying failures in reports #19 or #23. No physical-device or emulator test was performed during preparation; CI instrumentation APK assembly does not establish on-device transport, runtime startup or signed-upgrade behavior.
