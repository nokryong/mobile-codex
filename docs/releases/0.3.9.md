# 0.3.9

Android `versionCode 74`, ARM64, Android 10+.

- Includes the runtime recovery fix from [#29](https://github.com/nokryong/mobile-codex/issues/29): replacing a dead process or closed connection clears stale loaded-thread and running-turn state before resuming the saved conversation. This prevents sending a new turn to a thread that the replacement engine has not loaded. Saved conversation IDs and local history are retained; healthy connections keep their state.
- Error-report actions appear only when a report is available, including after the interface reloads. Successful submission consumes only the submitted report. Recovery clears the matching report without discarding a newer unrelated error, and chat recovery is matched to the conversation and registered running turn.
- Preview payloads remain frozen for explicit consent. Cancellation and matching recovery invalidate the previous consent; sending again requires a fresh preview. Failed submissions can retry the same report ID. Conversation correlation stays native-only and is excluded from previews, availability events and uploads.
- Startup and login preparation failures are captured before rollback, without stopping an unrelated existing runtime. Safe error categories remain distinct, and active versus pending login homes are identified from the actual runtime home.
- Keeps the existing schema-2, 27-field relay contract. Preparation stages unsupported by the current relay are represented as `unknown`; no relay deployment is required for this compatibility behavior. Raw errors, account details, conversation content, local identifiers, paths and tokens are not added to reports.

These changes improve report lifecycle and diagnostic accuracy. They do not establish or fix the unknown underlying causes of reports #19 or #23. No physical-device or emulator validation was performed during this release preparation. Automated checks and APK assembly do not establish on-device runtime, transport or signed-upgrade behavior.
