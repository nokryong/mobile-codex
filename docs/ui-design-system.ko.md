# Mobile Codex UI: 간격과 밀도

## 기준

색상·글꼴·제품 동작은 기존 Calm Workspace 계열을 유지한다. 간격은 [Carbon spacing](https://carbondesignsystem.com/elements/spacing/overview/)의 2/4/8/12/16/24px 척도를 바탕으로 작은 화면에서 읽고 조작하기 좋은 밀도를 정한다. Carbon 전체 테마나 컴포넌트를 도입하는 변경은 아니다.

사용자 요청은 앱 전체의 불필요한 gap/padding 축소와 깨진 레이아웃 수리다. 메뉴 몇 개만 수정하거나 화면을 축소해서 해결하지 않는다. [W3C Target Size (Enhanced)](https://www.w3.org/WAI/WCAG22/Understanding/target-size-enhanced.html)의 44×44 CSS px를 웹 주요 조작의 기존 목표로 유지한다. 이 숫자는 바깥 여백을 44px로 만들라는 뜻이 아니다. 인라인 링크·시스템 기본 UI·시트의 드래그 핸들은 별도 용도이며 준수 여부를 일괄 주장하지 않는다.

## 파일 역할

- `app.css`: 구조, 기능별 표시 상태, 상호작용, 기존 구성 요소.
- `visual-system.css`: 색, 글꼴, 표면, 강조, 시각적 형태.
- `spacing.css`: 웹 전체 공통 간격의 단일 출처. 기존 두 파일의 같은 선택자에 있던 margin/padding/gap 선언을 이곳으로 옮겼다. 같은 요소의 여백을 다른 파일 끝에 다시 덮어쓰지 않는다.
- `chat-web-custom.js`: 앱이 삽입하는 Chat/Codex 전환기만 관리한다. 외부 ChatGPT 전체 레이아웃을 일괄 재작성하지 않는다.
- 네이티브 뷰: Android dp로 간격을 지정한다. 키보드/시스템 inset, 플로팅 창의 위치 계산은 장식용 여백과 분리한다.

| 역할 | 값 | 적용 |
| --- | --- | --- |
| 작은 보조 간격 | 2px | 설명문, 같은 줄의 조작 |
| 가까운 요소 | 4px | 버튼 간격, 행 안쪽 세로 padding |
| 컴포넌트 내부 | 8px | 카드·입력칸·코드·목록 내부 |
| 그룹/패널 | 12px | 그룹 사이, 대화 패널, 일반 다이얼로그 |
| 넓은 화면 바깥쪽 | 16px | 데스크톱 대화 좌우 |
| 특별한 구분 | 24px | 시작 화면 위쪽, 프로젝트 대화 들여쓰기 |

화면 좌우는 16px, 760px 이하에서 12px, 360px 이하에서 8px다. 설정 카드 내부 8px, 설정 행 세로 4px, 버튼 사이 4px가 기본이다. 모델·전송 버튼은 44px 조작 영역 안에 32px 표시 면적을 유지한다. 고정 위치 컨트롤을 피하는 입력창의 52px 좌우 예약, 타임스탬프 예약, 드래그/시스템 inset은 기능상 예외다.

## 정리한 문제

- 뒤에 로드되는 스타일이 앞에서 줄인 간격을 다시 키우던 중복 선언을 공통 파일로 이동했다.
- 시작 화면의 화면높이 비례 48~140px 공백을 24px로 줄였다. 짧은 화면은 8px다.
- 대화 사이 23~24px를 12px로 정리하고, 대화문·코드·표·이미지·첨부도 같은 척도로 정리했다.
- 설정 행 12px 위아래 padding을 4px로 줄이고, 카드/그룹의 중복 문단 여백을 없앴다.
- 모바일 설정 탭은 여러 줄 격자로 콘텐츠를 밀어내던 구조에서 한 줄 스크롤 탐색으로 바꿨다. 내용은 다이얼로그 스크롤 하나로 접근한다.
- 모바일 파일 패널의 오래된 헤더 보정 때문에 생기던 이중 상단 공백을 제거했다.
- 프로젝트 선택 설명의 추가 좌우 20px 공백을 제거했다.
- 일반 버튼·계정 조작·카드 조작 등의 36~40px 터치 영역 회귀를 44px로 보정했다.
- MCP 질문의 체크박스에 텍스트 입력칸 너비와 padding이 적용되지 않도록 분리했다.
- GitHub 설정의 중첩 컨트롤에도 일정한 stack gap을 적용했다.
- 긴 초안의 입력창을 펼칠 때 높이를 다시 측정하고, 음성/첨부 패널이 보이는 동안 펼침 상태를 유지한다.
- 모바일 파일/이미지 편집기에 브라우저 기본 max-width가 남아 오른쪽 빈 띠를 만들던 문제를 제거한다.
- 설정 탭 전환 시 스크롤을 초기화해 앞 탭의 위치 때문에 새 제목이 가려지지 않도록 한다.
- 계정 한도는 API의 실제 초기화 날짜·시간을 기기 시간대로 표시한다. 168시간은 주간 한도 라벨로 바꾸며, 초기화 시각이 없으면 추정하지 않는다.

## 재현과 시각 검증

웹 기준 크기: 320×568, 393×852, 800×1100, 1280×900. 작은 높이/키보드 크기와 75/100/150% 글씨, 한국어/영어, 밝은/어두운 테마를 함께 점검한다. 고정 크기 스크린샷만으로 모든 조합을 확인했다고 기록하지 않는다.

- 기능 회귀: `npm test`
- 기존 브라우저 검사: `npm run test:layout`
- 전체 화면 검토용 로컬 서버: `node tools/ui_review_server.cjs`
- 추가 간격/화면 검사: `node tools/verify_spacing_browser.cjs`

Android 작업 환경에는 JDK·명령행 Chromium 실행 파일이 없다. 사용자가 켠 휴대폰 제어로 기기의 Chrome에서 loopback 검토 화면을 열어 확인한다. 이 경로는 실제 브라우저 렌더링이지만 설치된 Android 앱 빌드 검증은 아니다. 150% 글씨는 계산된 글꼴 크기를 먼저 저장한 뒤 배율을 적용하는 WebSettings.textZoom 대용 검사이며 네이티브 textZoom 자체와 구분한다. 브라우저/실기기 미실행을 통과로 표기하지 않는다.

## 2026-09-29 검증 기록

- JS 기능 회귀: 226개 통과(최신 원격 CI 검사, 동기화·한도 표시, 음성 입력 펼침 포함). Python 53개 중 49개 통과, 환경 조건부 4개 건너뜀.
- Android 기기 Chrome의 실제 렌더링: 36개 검토 표면 × 화면 크기 4종 × 테마 2종 × 글씨 2종 = 576개 조합에서 문서 가로 넘침, 열린 다이얼로그 경계, 주요 44px 조작 크기 검사 통과. 한국어 fixture이며 150%는 위에서 설명한 textZoom 대용 검사다.
- 원본 결과: `artifacts/ui-review/report.json` (로컬 검증 산출물, Git 제외). 애니메이션 완료·글꼴 로드·새 iframe 준비를 기다린 뒤 측정한다.
- `http://127.0.0.1:8765/gallery`는 모든 검토 표면을 3개씩 12페이지로 나누어 나란히 표시한다. 320×568 기본 글씨/밝은 테마의 각 표면을 기기 스크린샷으로 직접 비교했다. geometry 검사 통과는 모든 내부 요소의 시각 품질이나 실제 계정/네트워크 흐름 통과를 뜻하지 않는다.
- 네이티브 Java는 문법 파싱을 했으며 JVM/Robolectric·APK 빌드·수정 APK 설치 검증은 JDK 부재로 미실행이다.

외부 변경 `5bc2b6f`를 fast-forward로 반영한 뒤 작업 변경을 통합했다. 새 CI의 선행 검사·실패 즉시 중단·단일 APK 배포 흐름을 유지하고, 추가 UI 검사만 기존 실행기에 넣었다.
