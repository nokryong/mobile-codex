# Mobile Codex UI 디자인 기준

2026-09-28 기준. 이 문서는 앱이 직접 소유하는 Codex 화면에 적용합니다. Chat 모드는 ChatGPT 웹 화면이므로 여기서 시각 스타일을 변경하지 않습니다.

## 방향

**Calm Workspace / 차분한 작업 공간.** 대화와 파일 내용이 가장 먼저 읽히고, 실행·선택·위험 동작은 서로 구분되어야 합니다. 중립적인 녹색 표면과 뚜렷한 현재 위치를 쓰고, 시작 화면에만 Gentle Playful의 부드러운 카드 구성을 적용합니다. 금융 앱의 외형을 복제하지 않습니다.

제목·본문·조작 요소는 앱에서 이미 사용하던 `NotoSansKR-Regular`와 Android 시스템 대체 글꼴을 사용합니다. 코드에는 시스템 고정폭 글꼴을 씁니다. 장시간 읽는 개발 도구라서 Quiet Luxury의 큰 여백과 장식적 글꼴, Industrial Dashboard의 높은 밀도는 채택하지 않았습니다.

## 현재 화면 감사

| 화면/상태 | 소스에서 확인한 점 | 우선순위 |
| --- | --- | --- |
| 대화·입력창 | 중앙 메시지와 고정 입력창, 음성 입력·첨부·승인 방식·모델 설정이 공존합니다. 기존 미리보기에서 포커스를 잃으면 입력 도구가 사라져 주요 조작 영역이 작은 흰색 막대로 보였습니다. | 높음 |
| 프로젝트·대화 목록 | 선택 상태는 있지만 기본 hover 배경과 비슷하고, 스타일 값이 CSS 여러 지점에 반복됩니다. | 높음 |
| 설정·모델·권한 | 시트, 선택 카드, 계정·도구·업데이트가 있습니다. 선택 상태를 색과 접근성 속성으로 함께 드러낼 수 있습니다. | 높음 |
| 파일 탐색 | 모바일에서는 전체 폭 패널, 큰 화면에서는 오른쪽 패널입니다. 열림 상태가 버튼에 전달되지 않았습니다. | 중간 |
| 정상·빈 목록·작업 중·오류 | 기존 표시가 있습니다. 긴 번역과 큰 글자에서 모든 상태를 화면으로 다시 확인해야 합니다. | 중간 |

## 시각 규칙

값의 단일 출처는 `app/src/main/assets/web/visual-system.css`입니다. 기존 레이아웃과 개별 기능 스타일은 `app.css`에 두고, 공통 시각 규칙은 이 파일에서 관리합니다.

| 역할 | 값/사용처 |
| --- | --- |
| 기본 글자 | 본문 15px, 선택/버튼 14px, 보조 문구 12px, 시작 제목 25–30px |
| 간격 | 4·8·12·16·24px의 5단계. 같은 밀도의 요소는 같은 간격을 씁니다. |
| 모서리 | 조작 요소 12px, 콘텐츠 카드 18px, 입력창·시트 24px |
| 색 | 밝은 모드의 연한 녹색 작업 배경과 흰색 표면, 어두운 모드의 짙은 녹색 표면을 사용합니다. 주요 동작은 `--action`, 선택은 `--selected`와 `--selected-border`입니다. |
| 터치 | 핵심 터치 영역은 최소 44×44px. 아이콘 그림 크기와 실제 터치 영역을 별도로 취급합니다. |
| 움직임 | 상태 전환에만 짧게 쓰고 `prefers-reduced-motion`에서 제거합니다. |

## 공통 컴포넌트 규칙

1. **주요 동작:** 한 영역에 하나만 강조합니다. 전송·완료·저장처럼 현재 작업을 진행하는 버튼에 녹색 주요 동작 색을 씁니다. 삭제는 기존 위험 색과 확인 절차를 유지합니다.
2. **선택 항목:** 배경색뿐 아니라 글자 굵기·경계·`aria-current` 또는 선택 속성으로도 구분합니다. 비활성·선택 불가 상태를 선택 상태와 혼동시키지 않습니다.
3. **입력창:** 대화의 핵심 조작부로 고정하고, 포커스가 없어도 첨부·폴더·승인·모델·음성 도구를 보입니다. 포커스가 있으면 분명한 링을 표시하고, 키보드가 열린 320–420px 폭에서도 도구 버튼이 겹치지 않아야 합니다.
4. **시트·대화상자:** 제목, 설명, 선택지, 닫기/완료 순서로 읽힙니다. 모바일에서 손잡이와 닫기 버튼을 유지하며, 화면 밖으로 잘리지 않아야 합니다.
5. **텍스트:** 설명은 한 문장으로 짧게 씁니다. 긴 프로젝트명·대화 제목은 목록에서는 말줄임을 허용하되 해당 항목의 조작 버튼은 항상 보여야 합니다.

## 2차 적용 범위

- 시작 화면의 온보딩과 추천 작업을 카드형 그리드로 재구성했습니다.
- 사용자 요청과 Codex 응답을 분리해 읽기 순서를 분명히 하고, 입력 도구를 기본 상태에서도 표시합니다.
- 사이드바의 새 대화와 현재 대화를 더 쉽게 찾게 하고, 상단 프로젝트 맥락과 설정의 선택 상태를 같은 색 규칙으로 정리했습니다.
- 기능 흐름, 계정·권한 처리, 파일 조작 동작은 유지했습니다.

## 이어서 확인할 것

- 320/393px 휴대폰, 800px 태블릿, 큰 화면에서 라이트·다크, 한국어·영어, 긴 프로젝트명, 빈 목록, 작업 중·오류, 키보드 표시 상태를 시각적으로 비교합니다.
- 실제 기기에서 TalkBack, 큰 글꼴, 동작 줄이기, 시트 드래그, 파일 패널 열고 닫기를 확인합니다.
- 이번 감사는 소스 기준입니다. 사용자 과업 성공률이나 불편 빈도는 측정하지 않았으므로, 탐색 구조 자체를 바꾸기 전에는 실제 사용 흐름을 확인합니다.
