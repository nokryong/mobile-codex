# mobile-codex

Codex 데스크톱의 작업 방식을 Android 휴대폰·태블릿으로 옮기는 개인용 클라이언트입니다. 사용자가 Termux나 CLI를 설치하지 않도록 Codex 실행 엔진을 APK 안에 포함합니다.

**상태: 0.1.6 alpha (versionCode 7).** 프로젝트별 대화와 일반 대화를 분리하고, 오프라인 기록 열기, 여러 파일 첨부, `@` 파일·앱 멘션, `$` 스킬 선택을 추가했습니다. 입력창·프로젝트 서랍·모델 선택·설정 화면을 웹 ChatGPT와 Codex의 구성에 맞췄습니다. 0.1.0의 기본 실행·대화·파일 작업은 사용자 실기기 성공 보고가 있습니다. 이번 버전의 검증 범위와 실기기 미확인 항목은 [검증 기록](docs/verification.md)에 구분했습니다.

OpenAI 공식 Android 앱은 아닙니다. UI는 Codex 데스크톱의 프로젝트 사이드바·대화·입력창·파일 패널 구성을 참고했습니다.

## 설치

대상: **ARM64 Android 10 이상**, 최신 Android System WebView, 인터넷 연결.

1. 이 저장소의 **Actions → Android APK → 성공한 실행 → `mobile-codex-arm64-debug`**에서 APK 묶음을 받습니다.
2. 압축을 풀고 `app-debug.apk`를 설치합니다. Android가 요청하면 다운로드에 사용한 앱의 APK 설치 권한을 허용합니다.
3. 앱의 **ChatGPT 계정 연결**에서 표시되는 코드를 복사하고 브라우저에서 로그인합니다.
4. 폴더 없이 **일반 대화**를 시작하거나, 사이드바의 **프로젝트 추가**로 폴더를 등록합니다. 등록한 프로젝트는 목록에서 다시 선택할 수 있습니다. 로컬 프로젝트에서 셸 명령을 실행하려면 **설정 → 도구 → 기기 파일 접근 허용**도 설정합니다.
5. 입력창의 모델 버튼에서 모델·추론 강도·작업 권한을 선택합니다. `+`로 여러 파일을 첨부하고, `@`로 파일·앱을, `$`로 스킬을 선택할 수 있습니다.

계정은 Codex를 사용할 수 있어야 합니다. 모델 추론은 온라인 서비스에서 수행하고, Codex 프로세스와 도구 실행은 Android 기기에서 수행합니다. Termux, 별도 PC 서버, 앱 개발자의 중계 서버를 사용하지 않습니다.

현재 산출물은 개발용 서명 APK입니다. CI 실행마다 서명 키가 달라질 수 있어 업데이트가 거부되면 기존 앱을 지워야 할 수 있습니다. 앱을 지우면 앱 내부 대화·로그인·복구 사본이 지워지므로 일반 배포 전에는 고정된 배포용 서명을 구성해야 합니다.

| 화면 | 상태 표시줄·카메라 영역·탐색 바·키보드를 피하는 네이티브 레이아웃, 태블릿 다중 패널, 휴대폰 사이드바·설정 시트, 시스템/라이트/다크 테마 |
| 프로젝트·대화 | 여러 프로젝트 등록·전환·재연결, 프로젝트별 대화 트리, 폴더 없는 일반 대화, 로그인 없이 저장된 기록 열기, 응답 스트리밍·중지·재개 |
| 입력 | 대화별 텍스트·첨부·멘션·스킬·모델/추론 설정 보관, 다중 파일 선택·이미지 미리보기·개별 제거, 첨부만 전송, 실패 시 초안 보존 |
| 멘션 | `@` 프로젝트 파일·사용 가능한 앱 검색, `$` 활성 스킬 검색, 방향키·Enter·Escape 조작, 실제 구조화 입력 전달 |
| 이미지 | 생성 결과·MCP 이미지·로컬 이미지 표시, 여러 장 격자, 확대·썸네일·좌우 스와이프/버튼/키보드 이동, 개별 원본 저장 |
| 모델 | 계정에서 반환한 모델 목록, 지원되는 추론 강도 선택 |

| 파일 | Android 문서 제공자 폴더 탐색·검색·읽기·생성·수정·이름 변경·이동·삭제 |
| 실행 | 기본 Codex 도구 유지, Android 셸 명령 실행, 출력·종료 코드 확인 |
| 변경 검토 | app-server 작업 이벤트·diff 표시, 앱 편집기 변경 전 확인, 오래된 내용 덮어쓰기 방지 |
| 플러그인 | 마켓플레이스 조회·추가, 플러그인 상세·설치·제거·활성화, 필요한 앱 계정 연결 |
| 스킬 | 검색된 스킬 목록·활성화·대화 사용, `SKILL.md`와 보조 파일을 포함한 폴더 가져오기 |

앱 UI가 아직 전용 화면을 제공하지 않는 기능도 원래 Codex 도구·설정을 통해 사용할 수 있는 구조입니다. 기능 동작 여부는 포함된 실행 엔진, 계정, Android 권한, 설치된 명령에 달려 있습니다.

### 이미지와 업데이트

한 작업에서 반환된 여러 이미지 결과는 갤러리로 묶습니다. 각각 누르면 크게 볼 수 있고, 하단 썸네일·좌우 버튼·스와이프로 넘기거나 현재 이미지만 원본 파일로 저장합니다. 이미지가 일부만 성공한 경우 성공한 결과와 오류를 함께 표시합니다. 채팅의 로컬 Markdown 이미지와 파일 탐색기의 이미지 파일도 열 수 있습니다.

이미지 원본은 앱 내부에 보관하며 대화 기록에는 파일 참조만 저장합니다. 0.1.0에서 화면에 누락된 결과는 해당 대화를 다시 열 때 Codex 원본 기록에서 복원을 시도합니다. 실제 이미지 데이터나 원본 파일이 남아 있지 않으면 복원할 수 없습니다. 생성 자체의 사용 가능 여부는 Codex 엔진과 계정에 따릅니다.

기존 앱을 덮어 설치하려면 패키지명과 서명 인증서가 같아야 하며, 배포 시 `versionCode`를 증가시켜야 합니다. **GitHub Actions의 기본 debug APK와 별도 배포키로 서명한 APK는 서명이 다를 수 있습니다.** 배포자는 APK 체크섬과 서명 인증서 정보를 배포 파일과 함께 제공해야 합니다.

### 프로젝트·일반 대화·첨부

프로젝트 왼쪽 화살표는 대화 목록을 펼치고, 프로젝트 영역의 `+`는 새 폴더를 등록합니다. 프로젝트 이름을 누르면 등록한 폴더로 전환합니다. 각 프로젝트 안에서 새 대화를 만들거나 과거 대화를 열 수 있습니다. 폴더 접근 권한이 없어져도 기록은 남으며 **폴더 다시 연결**로 복구합니다. **일반 대화**는 프로젝트와 분리된 목록과 작성 공간을 사용합니다.

첨부 파일은 앱 내부에 원본 그대로 보관합니다. 이미지는 실제 `localImage` 입력으로, 문서·코드는 Codex가 읽을 수 있는 절대 경로로 전달합니다. 전송한 파일은 대화 기록에서 다시 보고 원본을 내보낼 수 있습니다. 첨부만 전송할 수 있으며 취소·부분 읽기 실패·전송 오류가 작성 중인 내용을 지우지 않습니다. 문서 형식별 해석에는 해당 처리 도구가 필요합니다. [입력 프로토콜과 저장 방식](docs/input-protocol.md)에 버전별 근거를 정리했습니다.

### 플러그인과 스킬

사이드바의 **플러그인 · 스킬 · MCP**에서 관리합니다. 카탈로그와 설치 상태를 app-server에서 읽습니다. 가짜 목록을 표시하지 않습니다.

- 플러그인: 상세 내용을 확인한 뒤 설치합니다. 추가 계정 연결이 필요하면 연결 버튼이 나타납니다.
- 스킬: `SKILL.md`가 바로 아래에 있는 폴더를 **스킬 가져오기**로 선택합니다. `scripts/`, `references/`, `assets/` 등도 함께 복사합니다. 저장 위치는 앱 내부 `CODEX_HOME/skills/<폴더명>`입니다.
- MCP: **서버 설정**에서 원래 Codex 설정을 편집할 수 있습니다. HTTP 서버는 원격 연결을 사용합니다. stdio 서버는 해당 명령이 기기에서 실행 가능해야 합니다.

## 플랫폼에 따른 차이와 남은 작업

기능을 임의로 숨기거나 차단하는 것을 목표로 하지 않습니다. 다만 Android가 데스크톱 OS와 같지는 않습니다.

- **Android 권한:** 다른 앱의 비공개 데이터, 시스템 보호 영역 등에 접근할 수 없습니다. 전체 파일 접근도 루트 권한이 아닙니다. 클라우드 문서 제공자는 일반 셸 경로가 없어서 `mobile_*` 문서 도구를 사용합니다.
- **샌드박스:** 현재 Android 포트에는 데스크톱의 Linux/macOS 명령 샌드박스가 없습니다. UI의 권한 모드는 Codex에 전달하는 작업 정책이며, 셸 프로세스의 실제 OS 경계는 Android 앱 권한입니다. 데스크톱과 같은 파일 격리를 보장하지 않습니다.
- **개발 도구:** 이 APK는 Codex·code-mode host·필요한 C++ 런타임을 포함합니다. Git·Node.js·Python·컴파일러를 모두 포함하는 개발 환경은 아직 구성하지 않았습니다. 따라서 이 명령을 요구하는 Git 마켓플레이스, 스킬 스크립트, stdio MCP는 추가 도구가 없으면 실패할 수 있습니다. 서버가 반환한 실제 오류를 표시합니다.
- **터미널:** 현재는 명령 입력과 출력 스트리밍입니다. 대화형 PTY, 터미널 에뮬레이션, 전경 프로그램 키 입력은 아직 구현하지 않았습니다.
- **앱 기능:** Git 전용 변경/커밋 화면, worktree 관리, 예약 자동화 UI는 아직 구현하지 않았습니다. 데스크톱 동등성 항목으로 추적하며 제품에서 영구 제외하는 기능은 아닙니다.
- **문서 편집기:** 내장 텍스트 편집기는 UTF-8 1 MiB, 문서 검색은 한 번에 3,000개 탐색/200개 결과로 메모리를 제한합니다. 직접 접근 가능한 프로젝트의 일반 Codex 도구·셸에는 이 편집기 한도를 적용하지 않습니다.
- **복구:** 앱의 문서 도구는 수정 전 파일 및 32 MiB 이하의 삭제 파일을 앱 내부에 복사합니다. 셸 변경, 큰 파일, 디렉터리 전체 삭제는 이 기능으로 백업하지 않습니다. 범용 실행 취소 기능이 아닙니다.
- **백그라운드:** 사용자 작업을 foreground service로 유지합니다. Android 및 제조사의 배터리 관리에 따라 중단될 수 있습니다.

실기기 검증 항목은 [docs/device-validation.md](docs/device-validation.md)에 정리했습니다.

## 개발 환경과 빌드

JDK 17, Android SDK Platform 35, Build Tools 35.0.0, Python 3, Node.js 20 이상이 필요합니다. Android Studio에서 이 디렉터리를 프로젝트로 열 수도 있습니다.

```sh
python3 tools/prepare_runtime.py
npm ci --ignore-scripts
npm test
python3 -m unittest discover -s tests -p 'test_*.py'
./gradlew assembleDebug testDebugUnitTest lintDebug assembleDebugAndroidTest
```

APK: `app/build/outputs/apk/debug/app-debug.apk`

프로젝트 전용 서명이 필요하면 빌드 프로세스에 `MOBILE_CODEX_KEYSTORE`(절대 경로), `MOBILE_CODEX_KEY_ALIAS`, `MOBILE_CODEX_STORE_PASSWORD`, `MOBILE_CODEX_KEY_PASSWORD`를 제공합니다. 값이 없으면 Android 기본 debug 서명을 사용합니다. 키와 비밀번호는 저장소 밖에 보관하며, 이 설정은 다른 프로젝트의 debug 키를 교체하지 않습니다.

ARM64 기기를 연결한 경우:

```sh
./gradlew connectedDebugAndroidTest
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

`RuntimeSmokeTest`는 별도의 테스트 홈에서 번들 실행 파일을 시작하고 JSON-RPC 초기화·로그아웃 상태의 계정 읽기를 확인합니다. 사용자의 로그인 파일을 사용하지 않습니다. CI의 일반 x86 Linux 러너는 Android ARM64 프로세스를 실행하지 않으므로 이 검사를 실행했다고 보고하지 않습니다.

## 실행 엔진과 출처

Android 엔진은 [DioNanos/codex-termux](https://github.com/DioNanos/codex-termux/tree/v0.155.1)의 `@mmmbuto/codex-cli-termux@0.155.1`입니다. 이름에 Termux가 있지만, 앱은 패키지의 Android 네이티브 ELF를 APK 라이브러리 디렉터리에 포함하여 직접 실행합니다. Termux 앱이나 npm 설치 스크립트를 실행하지 않습니다.

`tools/runtime-lock.json`에 정확한 버전·원본 URL·SHA-512를 고정했습니다. 준비 스크립트는 체크섬 및 ARM64 ELF 형식을 확인하고 필요한 파일만 추출합니다. 원본 LICENSE와 NOTICE를 APK에 포함합니다.

**패키징 변경:** Android가 네이티브 실행 파일을 `lib*.so` 이름으로 설치하므로, code-mode host를 `libcodexmodehostx.so`로 패키징합니다. 메인 ELF 안의 고정된 `codex-code-mode-host` 문자열 2곳을 같은 길이의 이름으로 바꿉니다. 섹션 크기와 오프셋은 유지합니다. 예상 문자열 개수가 다르면 빌드를 중단하고 검토를 요구합니다. 패치 후 각 파일의 SHA-256을 생성된 `assets/runtime/manifest.json`에 기록합니다. 바이너리를 직접 패치하는 이 부분은 장기적으로 동일한 이름 변경을 적용한 소스 빌드로 교체할 대상입니다.

프로토콜은 upstream [Codex app-server](https://github.com/openai/codex/tree/main/codex-rs/app-server)를 사용합니다. UI는 로컬 패키지 파일만 로드하고, Android 네이티브 코드가 JSON-RPC stdio·Android 파일 접근·로그인 브라우저를 담당합니다. 인증 정보는 앱 비공개 저장소에 보관하고 Android 백업·기기 전송에서 제외합니다.

## 개인 맞춤 지침과 컨텍스트 목록 (0.1.3)

설정 → 맞춤 지침에서 언어·말투·작업 규칙을 편집합니다. 앱 비공개 `files/.codex/AGENTS.md`를 실제 Codex 전역 지침으로 사용하며, 비어 있지 않은 `AGENTS.override.md`가 있으면 그 파일이 우선합니다. 화면에서 실제 적용 파일을 보여줍니다. 저장하면 엔진을 종료하고 다음 요청에서 지침을 다시 읽습니다.

기존 `files/codex`의 로그인·설정·스킬·기록은 `.codex`로 한 번만 복사하며, 기존 절대 경로 참조를 보존하기 위해 이전 폴더는 유지합니다. 새 홈의 파일을 덮어쓰지 않습니다. 완료 표시 후에는 로그아웃으로 지운 인증 파일을 이전 홈에서 다시 가져오지 않습니다.

`@`를 입력하면 현재 프로젝트의 파일·폴더와 사용 가능한 연결 앱 목록이 열립니다. 폴더를 열거나 이어서 입력해 검색할 수 있습니다. `$`는 활성화된 스킬 이름과 설명을 표시하며, 스킬 가져오기도 제공합니다. 연결 응답이 늦더라도 로컬 파일부터 표시하고, 빈 결과·조회 오류도 목록에서 안내합니다.

## 대화 아이콘 (0.1.5)

설정 → 일반 → **대화 아이콘** 스위치로 캐릭터 표시를 켜거나 끕니다. 기본은 켜짐이며 앱을 다시 열어도 유지됩니다. 답변, 시작 화면, 작업 상태에 적용되며 생성 이미지와 첨부 사진은 끄지 않습니다.

`app/src/main/assets/web/chat-icons/`의 PNG 32종을 앱에 포함합니다. 표정은 응답 문구 및 실제 작업 상태에 따라 UI가 선택하는 장식이며 모델의 감정이나 도구 성공 여부를 판단하는 기능은 아닙니다. 이미지 생성 갤러리 및 모델 입력과 분리되어 있고 외부 이미지 요청을 하지 않습니다.

## 저장소에 포함하는 파일

앱 소스와 실행에 필요한 이미지, 테스트, 빌드·CI 설정, 런타임 준비 도구 및 사용·개발 문서를 관리합니다. 이미지 제작 원본과 프롬프트(`sheet/`), 빌드 산출물(`artifacts/`), 개인 설정·로그·서명키·인증 파일은 커밋하지 않습니다. APK에 필요한 32종 아이콘은 제작 원본 폴더와 별도로 포함되어 있어 해당 폴더 없이 빌드할 수 있습니다.
